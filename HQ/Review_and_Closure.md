# 검토와-종료

## overview

HQ가 작업의 현황을 보고, 끝난 결과를 검토하고, 작업을 닫거나 후속 작업으로 넘기는 방법입니다. 작업이 어떤 상태를 거치는지는 [작업 상태](../Architecture/Command_and_Report_Flow.md#작업-상태)에 있습니다.

| 섹션 | 내용 | 적용 |
|---|---|---|
| [현황-보기](#현황-보기) | 현황 요약과 `hq` 값별 할 일 | 운영 매뉴얼 |
| [결과-검토](#결과-검토) | 검토 대기 작업에서 확인할 것 | 운영 매뉴얼 |
| [종료-취소-보류](#종료-취소-보류) | 작업의 결말과 상태 | 운영 매뉴얼 |
| [정본-승격-확인](#정본-승격-확인) | 결과가 정본에 반영됐는지 | 운영 매뉴얼 |
| [후속-제안-처리](#후속-제안-처리) | 남은 일을 다음 제안으로 넘기는 규칙 | 운영 매뉴얼 |
| [관련-문서](#관련-문서) | 명령과 기록 형식 | 운영 매뉴얼 |

## 현황-보기

- **채팅:** [`{status-command}`](../Architecture/Company_Profile.md#도구-설정)를 보내면 AI가 TaskNote frontmatter를 직접 읽어 요약합니다.

- **뷰:** 작업 관리 도구의 뷰에서 결정 대기 작업을 봅니다 ([작업 관리](../Architecture/Workspace_and_Tools.md#작업-관리)).

- **주간 점검 (요청할 때):** 7일 넘게 멈춘 작업, HQ 대기 작업, [쓰기 범위](Control_Settings.md#쓰기-범위)가 겹치는 작업 목록을 AI에게 요청합니다.

| `hq` 값 | HQ가 할 일 |
|---|---|
| `decide` | 결정표를 채우거나 승인 ([결정표 작성](Commands_and_Approval.md#결정표-작성)) |
| `dispatch` | 실행 지시를 보내거나 그대로 둠 |
| `review` | 결과 검토 ([결과 검토](#결과-검토)) |
| `none` | 할 일 없음 |

## 결과-검토

`hq: review` 작업은 산출물이 끝났고 HQ 확인만 남은 상태입니다.

| 확인할 것 | 볼 곳 |
|---|---|
| 원래 완료 기준을 모두 충족했나 | `# 기록`의 검증 항목 |
| 바뀐 파일이 쓰기 범위 안인가 | `# 기록`의 변경 파일 |
| 미해결이나 다음 인계가 남았나 | `# 기록`의 미해결·다음 인계 |
| 정본에 반영했나 | [정본 승격 확인](#정본-승격-확인) |
| 사실, 추정, 권장이 구분되어 있나 | [사실·추정·권장](../AI/Reporting_Style.md#사실-추정-권장) |

- **통과:** HQ가 검토 완료를 알리면 AI가 작업을 `done / none / none`으로 닫습니다.

- **수정 요구:** `수정:`으로 고칠 점을 보내면 새 버전으로 결정 대기가 됩니다 ([수정과 중단](Commands_and_Approval.md#수정과-중단)).

## 종료-취소-보류

| 결말 | 조건 | 상태 |
|---|---|---|
| 완료 | 원래 완료 기준과 검증을 모두 충족 | `done / none / none` |
| 검토 대기 | 산출물은 끝났고 HQ 검토가 남음 | `done / {hq-owner} / review` |

AI는 원래 완료 기준과 검증이 끝난 뒤에만 작업을 닫습니다. `{hq-owner}` 값은 [회사 프로필](../Architecture/Company_Profile.md#사람과-역할-배정)에 있습니다.

### 보류와-취소-확장

| 결말 | 조건 | 상태와 기록 |
|---|---|---|
| 보류 | HQ가 결정을 미룸 | `to-do / {hq-owner} / decide` 유지, 다시 볼 조건을 기록하고 제안을 반복해 만들지 않음 |
| 취소 | HQ가 명시적으로 취소 | `done / none / none`, report 결과 첫 줄에 `취소`와 사유. 완료 성과에서 제외 |
| 검증 실패 | 완료 기준 미충족 | 완료로 바꾸지 않음. 기준을 실제로 충족하거나 HQ가 목표를 바꾸거나 종료한 기록이 있어야 닫음 |

## 정본-승격-확인

| 결과의 종류 | 반영할 곳 | 규칙 |
|---|---|---|
| 프로젝트의 현재 상태 | [STATUS](../Architecture/Document_System.md#정본-문서) 본문 | AI가 근거 링크와 함께 갱신 ([위험도](../Architecture/Risk_and_Authority.md#위험도) 1) |
| STATUS의 상태·단계·우선순위·마감 필드 | STATUS frontmatter | 결정표로 제안만 하고 HQ가 결정 (위험도 2) |
| HQ가 내린 결정 | Decisions | `DEC-<ID>-NNN`으로 기록 |
| 재사용할 지식 | Technical·Theory Wiki | 원본을 복제하지 않음 |

AI 분석만으로 프로젝트 상태를 바꾸지 않으며, 원 증거를 확인한 뒤에만 반영합니다. HQ는 `# 기록`에 반영한 문서 링크가 있는지 확인합니다.

## 후속-제안-처리

`# 기록`의 미해결이나 다음 인계가 "없음"이 아니면 AI는 다음과 같이 처리합니다.

| 상황 | AI가 하는 일 |
|---|---|
| 결과·산출물·쓰기 범위가 같음 | minor 버전을 올려 같은 TaskNote에 다음 버전 제안 1개를 씀 |
| 결과·산출물·쓰기 범위가 다름 | 새 TaskNote를 만들고 원래 작업을 링크 |
| 같은 내용의 열린 후속 작업이 이미 있음 | 그 작업을 갱신하고 새로 만들지 않음 |
| 제안 승인이나 산출물 검토만 남음 | 제안서를 다시 만들지 않음 |

- **묶음:** 한 보고에서 나온 후속 작업은 한 제안으로 묶고, HQ 결정·행동은 10개 이하로 보여 줍니다.

- **실행 금지:** 후속 제안은 승인 전에 실행하지 않습니다.
