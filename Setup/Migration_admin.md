# 이전-절차

## overview

기존 작업 공간을 승인된 프로토콜에 맞추는 절차입니다. 이 문서는 이전 실행 매뉴얼이며 실제 파일 목록·이동 대응표·Git 기준점은 실행 직전에 작업 노트에 작성합니다.

|---|---|---|
| [선행-조건](#선행-조건) | 충돌·동시 작업·백업 확인 | 운영 매뉴얼 |
| [이전-대응표](#이전-대응표) | 변경 대상과 경로 대응 | 운영 매뉴얼 |
| [파일럿](#파일럿) | 합성 작업과 실패 경로 | 운영 매뉴얼 |

## 선행-조건

| 조건 | 확인 근거 | 실패 시 |
|---|---|---|
| 승인 범위 | 체크리스트·고정 commit·회사 프로필·이전 대응표 | 준비만 진행, 이전 금지 |
| 충돌 없음 | 대상 파일 내 충돌 표시·인덱스 충돌 검사 | 별도 복구 작업으로 해결 |
| 다른 작업 보존 | 부모·submodule 상태, 실행 중 Agent·job 목록 | 겹치는 작업 중지 또는 순서 조정 |
| 복구 가능 | tracked commit, untracked·ignored·바이너리 snapshot, hash | 백업과 표본 복원 후 시작 |
| 편집·동기화 | 파일 이동 동안 편집기·자동 동기화 쓰기 정지 | 파일 이동 시작 금지 |

Git 연결이나 파일 개수는 특정 기기의 과거 기록을 재사용하지 않고 실행 환경에서 다시 확인합니다. 백업은 Git commit만으로 제외 파일까지 보존된다고 간주하지 않습니다.

## 이전-대응표

| 영역 | 권장 조치 | 경계 |
|---|---|---|
| 최상위 폴더 | 기존 HQ·INBOX·PROJECTS·Wiki·기관 영역·ARCHIVE 유지 | 승인 없는 전면 이름 변경 없음 |
| 진입 파일·CONTEXT | 채택된 프로토콜과 로컬 프로필로 연결 | 같은 규칙을 여러 곳에 복사하지 않음 |
| 기존 AI_Control 규약 | 이전 내용은 Git 이력·백업 보존, 본문은 정본으로 가는 안내로 전환 | 실제 정본 전환은 마지막 활성화 단계 |
| TaskNote | 열린 작업부터 필드 대응, 제목·기존 경로 보존 우선 | legacy 이력 일괄 이동하지 않음 |
| 템플릿·뷰 | 실제 생성 예제와 필터 검사 | `done + hq: review` 누락 방지, 템플릿·교환 기록 색인 제외 |
| 프로젝트·자료 | [배치 판단](../Architecture/Workspace_Layout_admin.md#배치-판단)으로 중복 후보만 제안 | 원본 보존·기밀 경계 유지 |
| Git repo | 승인된 경우에만 git mv와 .gitmodules 갱신 | Explorer 이동 금지, 안쪽부터 push |

작업 노트에 다음 열을 가진 **실제 파일별** 대응표를 만듭니다. 이 표가 없으면 전체 재구조화를 실행하지 않습니다.

```text
기존 경로 | 새 경로 | 유지/수정/이동/휴지통 | 이유 | Git/submodule/ignored
기밀 등급 | 기존 hash | 백업 위치 | 영향 링크·Canvas·설정 | 검증 | 복구 방법
```

표에 없는 파일은 그대로 둡니다. 계획 작성 후 입력이 바뀌면 diff를 다시 확인하고 범위 변경분만 재승인합니다.

## 파일럿

| 경우 | 기본 모드 기대 결과 | 확장 모드 추가 기준 |
|---|---|---|
| 정상 텍스트 수정 | 지시→백업→실행→증거→종료 | instruction→plan→evaluation→execution→verification→report |
| 미승인 위험도 2 | 계획은 작성, 실제 수정·전송 0 | 평가 pass라도 실행 gate가 거부 |
| 경량 작업 | TaskNote 하나에 기록 | 가짜 평가·교환 기록 불필요 |
| 중단·재개 | 완료 단계 확인, 성공 단계 중복 실행 0 | checkpoint·성공 receipt hash 검증 |
| 검증 실패 | 미완료 상태와 보완 근거 | 한도 누적, 과거 run으로 초기화 금지 |
| 부모 편집·중복 요청 | 사용자 수정 보존 | 기록 1개만 발행, 색인 복구, 만료된 잠금 작성 거부 |

확장 모드를 선택하면 Router의 [전체 시험](../AI/Routing_agent.md#시험)을 별도 구현·통과해야 합니다. 이 문서 검토만으로 구현 완료로 표시하지 않습니다.

## 실행과-복구

1. 승인된 대응표·프로토콜 commit·프로필 hash와 실행 지시를 기록합니다.
2. 관련 범위의 편집을 멈추고 백업을 검증합니다. 원본·제외 파일을 임시 복원 경로에서 표본 확인합니다.
3. 소규모 비기밀 영역에서 먼저 이전하고 링크·설정·작업 상태를 확인합니다.
4. 승인된 묶음별로 수행하고 이동 로그·전후 hash·검증 결과·commit을 남깁니다. submodule은 안쪽 commit을 먼저 원격에 보존합니다.
5. 실패하면 다음 묶음을 시작하지 않습니다. 변경된 파일을 안전하게 보존하고, 이후 사용자 수정과 비교해 승인된 변경분만 복구합니다. 이력 강제 재작성·reset으로 통째로 덮어쓰지 않습니다.
6. 모든 검증을 통과한 뒤 진입 파일·정본 안내·로컬 채택 상태를 함께 활성화하고 HQ에 결과를 보고합니다.

복구 범위가 승인된 계획을 넘거나 사용자 수정과 충돌하면 자동 복구를 멈추고 선택지를 기록합니다.

## 완료-기준

- [ ] 대응표의 모든 파일이 보존되며 원본·기밀 자료 손실 0
- [ ] 이동 전후 링크 비교에서 새 깨진 링크 0, Canvas·설정 참조 검증
- [ ] 진입 파일·CONTEXT·템플릿이 같은 채택 commit과 프로필을 참조
- [ ] 작업 상태 조합·의존성·HQ 검토 뷰 정상, 템플릿과 교환 기록이 작업으로 색인되지 않음
- [ ] Git·submodule commit·원격·복구 지점 확인, 실제 표본 복원 성공
- [ ] 로컬 채택 기록과 Decisions에 활성화 근거·남은 예외·운영 모드 기록
