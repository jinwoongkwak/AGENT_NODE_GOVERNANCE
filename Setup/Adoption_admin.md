# 채택과-버전-고정

## overview

문서를 배포한 상태와 회사가 실제 운영에 채택한 상태를 구분합니다. 체크 표시만으로 실행이 시작되지 않으며, 검토한 commit과 구체적인 실행 범위를 기록해야 합니다.

| 섹션 | 내용 | 적용 |
|---|---|---|
| [적용-상태](#적용-상태) | 초안·승인·활성화 | 운영 매뉴얼 |
| [버전-구분](#버전-구분) | 프로토콜·회사·작업·스키마 | 운영 매뉴얼 |
| [승인-기록](#승인-기록) | 로컬 기록 양식과 승인 효력 | 운영 매뉴얼 |
| [업데이트](#업데이트) | 새 버전과 기존 기록의 관계 | 운영 매뉴얼 |
| [관련-문서](#관련-문서) | 검토·이전 | 운영 매뉴얼 |

## 적용-상태

| 상태 | 뜻 | 허용 |
|---|---|---|
| draft | 검토용 문서 | 개선·검사·배포. 기존 운영 규칙 유지 |
| approved | 특정 버전·선택·이전 범위를 HQ가 승인 | 승인된 준비 작업. manual이면 실제 이전 지시 대기 |
| active | 이전·검증 후 회사 정본으로 활성화 | 승인된 모드와 조항만 운영 |

문서의 `운영`은 현재 공통 매뉴얼의 적용 범위입니다. 새 회사의 실제 운영 권한은 로컬 채택 기록으로 확정합니다. 이 구분은 [최상위 상태 표시](../README.md#상태-표시)와 함께 읽습니다.

## 버전-구분

| 값 | 대상 | 변경 시점 |
|---|---|---|
| 프로토콜 release + commit | 공통 규칙·템플릿 | 저장소 문서 변경 |
| 회사 채택 버전 | 적용 commit·프로필·예외·도입 모드 | HQ가 운영 선택을 변경 |
| 작업 계약 버전 | 한 작업의 목표·범위·권한 | [작업 버전 규칙](../HQ/Commands_and_Approval_admin.md#버전-규칙) |
| 스키마 번호 | 교환 기록 형식 | 비호환 규칙 변경 |

확장 모드의 각 instruction은 프로토콜 commit·스키마 번호·로컬 프로필 hash를 고정합니다. 프로토콜 업데이트가 실행 중인 작업의 계약·승인·한도를 바꾸지 않습니다.

## 승인-기록

아래 틀을 회사 저장소의 로컬 채택 기록으로 사용합니다. 실제 값은 HQ 원문에서 채우고 빈칸을 AI가 승인으로 채우지 않습니다.

```markdown
# 프로토콜 채택

| 항목 | 값 |
|---|---|
| 상태 | draft |
| 회사 채택 버전 | V1.0.0 |
| 프로토콜 release | 1.0.0 |
| 검토 commit | <40자리 SHA> |
| 로컬 프로필 위치·SHA-256 | <값> |
| 도입 모드 | 기본 / 확장 |
| C1–C10 | 검토한 README 체크리스트 링크·선택·예외 |
| 승인자·시각·원문 | <HQ가 실제 승인한 내용> |
| 실행 범위 | <이전 TaskNote 및 대응표 버전·hash> |
| 실행 지시 | 미수신 |
| 활성화 근거 | 미활성, 검증 후 commit·결과 링크 |
```

체크리스트는 검토 진행 상태이고, 위 기록이 채택 결정을 보존합니다. 승인 후 의미·권한·범위가 바뀐 항목은 해당 체크를 해제하고 변경분을 재검토합니다. 이미 승인된 관계없는 항목은 다시 묻지 않습니다.

## 업데이트

1. 새 commit의 차이와 호환성을 검토하고 로컬 프로필·예외에 미치는 영향을 기록합니다.
2. 합성 파일럿과 문서 검사를 수행합니다.
3. HQ 승인 후 새 작업부터 적용하며, 진행 중 작업은 고정된 버전을 유지합니다.
4. 과거 교환 기록은 당시 스키마로 읽습니다. 최신 스키마에 맞추려고 불변 기록을 다시 쓰지 않습니다.
