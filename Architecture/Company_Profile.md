## 회사-정보

회사명·연구 질문·프로토콜 버전은 회사 저장소의 로컬 `Company_Profile.md`와 `company.json`에서 지정합니다. 이 공통 저장소에는 특정 회사의 운영 값을 고정하지 않습니다.

## 사람과-역할-배정

`{hq-person}`은 실제 관리자, `{hq-owner}`는 작업의 owner 값입니다. `ai`, `none`과 다른 값을 사용합니다. 기본 모드는 단일 Agent, 확장 모드는 시험된 역할별 호출을 사용합니다.

## 작업-공간-경로

| 이름 | 지정할 값 |
|---|---|
| `{workspace-root}` | 실제 회사 작업 공간 절대 경로 |
| `{entry-files}` | AGENTS.md, 필요 시 CLAUDE.md |
| `{protocol-folder}` | 공통 매뉴얼 폴더 |
| `{legacy-control-folder}` | 구형 규약 안내·호환 경로 |
| `{task-folder}`, `{task-views}`, `{templates}` | TaskNote·HQ 뷰·템플릿 폴더 |
| `{decision-log}`, `{project-index}`, `{context-file}` | 결정·프로젝트 색인·영역 CONTEXT |
| `{trash}`, `{assets-folder}` | 휴지통·대용량 자료 위치 |
| `{runtime-dir}`, `{router}`, `{checkpoint-dir}` | 확장 모드에서만 지정; 기본 모드는 미사용 |

새 회사의 기본값은 [생성기](../tools/bootstrap.py)와 [예제 설정](../Setup/company.example.json)을 사용합니다. 기존 회사는 실제 경로를 보존하며 로컬 프로필에 기록합니다.

## 영역과-정본

HQ·프로젝트·Technical Wiki·Theory Wiki·INBOX·Archive의 역할은 [작업 공간 구조](Workspace_Layout.md)에 있습니다. 기관·개인·심사 영역은 회사가 필요할 때만 추가하며 기밀 경계를 함께 지정합니다.

## 프로젝트-키

각 프로젝트에 변하지 않는 ID, 실제 README 경로, 경로 prefix, task 저장 위치를 연결합니다. 자체 연구와 외부 주도 협업을 구분하며 기존 번호를 재사용하지 않습니다.

## 기밀-영역

기밀·NDA·라이선스·개인 자료의 실제 경로, 허용된 읽기 환경, 외부 전송 제한을 로컬 프로필에 적습니다. 미확인은 “없음”이 아닙니다. [공통 규칙](../AI/Common_Rules.md#기밀)을 따릅니다.

## 도구-설정

| 값 | 지정할 내용 |
|---|---|
| 편집기·작업 관리 | 실제 버전·태그·필드 매핑·템플릿 제외 경로 |
| `{status-command}` | 예: TaskNotes 현황 보여줘 |
| `{record-link-format}` | 회사 내부 기록의 링크 형식. 공통 매뉴얼은 상대 Markdown 링크 |
| Python·Git·동기화 | 실제 실행 파일·버전·백업·실행 기기 |

TaskNotes를 사용하면 `blockedBy`는 task 링크 목록으로 사용하고 외부 대기 조건은 본문에 적습니다. 기밀 설정이나 자격증명은 공통 repo에 넣지 않습니다.

## 버전-관리-설정

| 이름 | 지정할 값 |
|---|---|
| `{remote}` | 회사 저장소 URL |
| `{main-branch}` | 정본 브랜치, HQ 병합 |
| `{ai-branch}` | AI 작업 브랜치, 기본 ai/work |
| `{git-data}` | Git 데이터 위치와 동기화 제외 정책 |
| `{large-file-limit}` | staged 파일 상한, 기본 25MB |

기밀·제외 자료와 submodule 경계, 저장소 목록·원격 접근 조건을 함께 기록합니다. Git 저장소가 있다는 사실만으로 ignored 파일도 백업된다고 보지 않습니다.

## 명명-규칙

프로젝트 ID·문서·날짜·데이터·결정 ID·repo 이름을 로컬 프로필에서 지정합니다. 기본 프로젝트 ID는 `PYYNN_SHORTNAME`, 결정은 `DEC-<영역>-NNN`, TaskNote는 할 일을 나타내는 제목입니다. 기존 파일을 일괄 이름 변경하지 않습니다.

## 근거-자료

공통 매뉴얼은 과거 설계 제안과 운영 경험을 통합했습니다. 특정 회사의 DEC나 과거 승인 자체를 새 회사에 이식하지 않습니다. 실제 채택 근거는 회사 저장소의 [채택 기록](../Setup/Adoption.md#승인-기록)에 보존합니다.

## 알려진-문제

실행 환경의 충돌·설정·미구현 기능은 로컬 프로필에서 관리합니다. 현재 공통 패키지는 기본 모드·문서 검사·새 회사 생성·구조 검사·진입점 생성을 제공하고, Router 자동 운영은 설계만 제공합니다.
