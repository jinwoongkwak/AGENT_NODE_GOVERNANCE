# 명령과-승인

## overview

HQ가 AI에게 지시하고, 제안서를 읽고, 결정·승인·실행 지시를 전하는 방법입니다. 이 명령들이 오가는 전체 흐름은 [명령과 보고 체계](../Architecture/Command_and_Report_Flow_admin.md#전달-체계-한눈에)에 있습니다.

| 섹션 | 내용 | 적용 |
|---|---|---|
| [채팅-명령](#채팅-명령) | HQ가 쓰는 명령 7개 | 운영 매뉴얼 |
| [제안서-읽는-법](#제안서-읽는-법) | 제안서에서 먼저 볼 곳과 확인 질문 | 운영 매뉴얼 |
| [결정표-작성](#결정표-작성) | 결정표 형식과 조건 붙이는 법 | 운영 매뉴얼 |
| [승인과-실행-지시](#승인과-실행-지시) | 승인이 무엇을 허락하는지 | 운영 매뉴얼 |
| [수정과-중단](#수정과-중단) | 방향을 바꾸거나 멈추는 법 | 운영 매뉴얼 |
| [버전-규칙](#버전-규칙) | 제안·승인 버전을 올리는 기준 | 운영 매뉴얼 |
| [관련-문서](#관련-문서) | 설정과 검토 | 운영 매뉴얼 |

## 채팅-명령

| HQ가 보내는 말 | AI가 하는 일 | 자동 실행 |
|---|---|---|
| `초안: <요청>` | 할 일을 바로 나타내는 제목으로 [TaskNote](../Architecture/Document_System_admin.md#작업-문서)를 만들고 결정 대기에서 멈춤 | 아니요 |
| `승인: <제목> <버전>, Q1=A…` | 결정과 승인 버전을 기록 | after-approval일 때만 |
| `<제목> 실행해` | manual 작업의 승인된 버전을 실행 | 예 |
| `수정: <제목> <내용>` | 제안 버전을 올리고 이전 승인을 무효로 한 뒤 결정 대기 | 아니요 |
| `상태: <제목>` | `# 현재 상태`를 요약 | 아니요 |
| `중단: <제목>` | 안전한 지점에서 멈추고 결과·복구 방법·다음 행동을 기록 | 작업을 멈춤 |
| [`{status-command}`](../Architecture/Company_Profile_admin.md#도구-설정) | TaskNote frontmatter를 직접 읽어 HQ 행동과 상태별로 요약 | 아니요 |

- **명령 없이 요청해도 됩니다.** 일반 대화로 요청해도 AI는 행동하기 전에 TaskNote부터 만듭니다.

- **manual 작업은 승인이 실행을 뜻하지 않습니다.** [실행 모드](../Architecture/Risk_and_Authority_admin.md#실행-모드)를 확인합니다.

## 제안서-읽는-법

제안서는 결정표가 있는 TaskNote입니다. 아래 순서로 읽으면 전부 읽지 않고도 결정할 수 있습니다.

| 순서 | 볼 곳 | 확인할 질문 |
|---:|---|---|
| 1 | `# 현재 상태` | 무엇이 바뀌고, 무엇이 막혀 있나 |
| 2 | `# 결정 및 승인`의 결정표 | 내가 고를 것은 몇 개이고, AI 권장은 무엇인가 |
| 3 | 질문별 선택지 설명 | 각 선택의 실제 결과·장점·부담이 구체적인가 |
| 4 | 이월 행 | 예전에 이미 결정한 것을 다시 묻고 있지 않은가 |
| 5 | `# 실행 계획` | 승인하면 바로 실행되나 ([실행 모드](../Architecture/Risk_and_Authority_admin.md#실행-모드)), 되돌릴 수 있나 |
| 6 | `# 근거` | 필요할 때만 |

### 결정-요청-형식-확장

[과정 역할](../Architecture/Organization_admin.md#과정-역할)을 도입하면 결정 요청은 질문 1개와 멈춘 이유, 선택지별 영향, AI 권장과 근거, 응답이 없을 때의 상태, 결정 후 재개 지점을 한 화면에 담습니다 ([결정 요청 형식](../AI/Roles/Coordinator_agent.md#결정-요청-형식)).

## 결정표-작성

```markdown
| # | 질문 | 선택지 | AI 권장 | 결정 |
|---|---|---|---|---|
| Q1 | 구현 방식 | A. … / B. … / C. … | A | A, 반복 상한은 2회 |
```

- **조건 붙이기:** 결정 칸에는 선택 글자만 쓸 필요가 없습니다. `A, 반복 상한은 2회`처럼 조건을 함께 적을 수 있습니다.

- **조건의 반영:** 의미가 달라지는 조건은 AI가 실행 계획에 반영하고, 관련 없는 기존 선택은 다시 묻지 않습니다.

- **상한:** 한 TaskNote에서 HQ가 처리할 결정과 행동은 합쳐 10개 이하입니다 ([주의력 예산](HQ_Role_admin.md#주의력-예산)).

- **답하는 곳:** 결정은 대표 TaskNote의 결정표 한 곳에만 적습니다.

## 승인과-실행-지시

승인은 제안된 버전을 채택하는 행위이며, AI는 결정과 `approved_version`을 기록합니다. 승인 뒤에 실행이 시작되는지는 실행 모드가 정합니다.

| 실행 모드 | 승인하면 | HQ가 더 할 일 |
|---|---|---|
| autonomous | [위험도](../Architecture/Risk_and_Authority_admin.md#위험도) 0–1은 승인 없이도 작성된 task대로 실행 | 없음 |
| after-approval | 승인이 곧 실행 권한 | 없음 |
| manual | 계획만 기록되고 실행 지시 대기 (`hq: dispatch`) | `<제목> 실행해` |

- **명시 요청의 효력 (C2 승인):** 현재 대화에서 HQ가 대상·범위·행위를 구체적으로 실행하라고 지시했다면 그 원문과 시각을 기록하고 해당 범위에 대한 승인·실행 권한으로 사용합니다. 형식 명령을 다시 요구하지 않습니다. “검토 후 승인하면” 같은 조건부 요청은 그 조건이 충족되기 전까지 실행 권한이 아닙니다.

- **승인되지 않은 상태:** `approved_version: ""`를 사용합니다. AI가 자기 제안 버전을 복사해 HQ 승인으로 표시하지 않습니다.

- **실행 전 확인:** 위험도 1–2 작업은 실행 전에 AI가 `# 현재 상태`에 결과, 제외, 승인 버전, 중단 조건, 보고 시점을 적습니다.

- **승인의 범위:** 승인은 그 버전의 결과·산출물·[쓰기 범위](Control_Settings_admin.md#쓰기-범위)·위험도에만 적용됩니다. 이 중 하나라도 바뀌면 새 승인이 필요합니다.

## 수정과-중단

- **수정:** `수정:`을 보내면 AI가 제안 버전을 올리고 이전 승인을 무효로 한 뒤 결정 대기로 돌아갑니다. 바뀐 내용의 크기에 따라 [버전 규칙](#버전-규칙)을 적용합니다.

- **중단:** `중단:`을 보내면 AI가 안전한 지점에서 멈추고 결과, 복구 방법, 다음 행동을 기록합니다.

- **다시 시작:** manual 작업은 `실행해`로 다시 시작하고, 계약이 바뀌었으면 새 승인을 받습니다.

### 수정-범위-확인-확장

`수정:`이 무엇을 바꿨는지 불명확하면 AI는 진행 중인 실행을 멈추고 변경 범위를 확인합니다. 재개할 때는 저장해 둔 [checkpoint](../AI/Roles/Coordinator_agent.md#checkpoint와-재개)와 현재 입력을 비교합니다.

## 버전-규칙

| 변경 | 버전 | 예 |
|---|---|---|
| 승인 경계 안에서 지시 → 실행 → 보고 한 번 | patch | `V1.0.0` → `V1.0.1` |
| 미해결·인계 작업의 [후속 제안](Review_and_Closure_admin.md#후속-제안-처리) | minor, patch는 0으로 | `V1.0.3` → `V1.1.0` |
| 새 결과나 새 운영 체계 | major, minor·patch는 0으로 | `V1.4.2` → `V2.0.0` |

- **기록:** 모든 기록에 지시·보고 버전과 승인 버전을 함께 적습니다.

- **권한:** 실행·보고의 patch 번호는 승인된 계약 번호와 별도로 기록합니다. patch 보고 때문에 `approved_version`을 바꾸지 않으며, 승인 snapshot에 계약 버전과 연결합니다. patch 기록은 권한을 넓히지 않습니다. 결과·산출물·쓰기 범위·위험도가 바뀌면 새 승인이 필요합니다.

### 내부-반복-버전-확장

과정 역할 사이의 계획 수정, 재평가, 재실행은 버전을 올리지 않고 [교환 기록](../Architecture/Document_System_admin.md#교환-기록)의 순번으로 추적합니다. 범위·기준·권한·예산이 바뀌는 minor와 목표가 바뀌는 major만 새 run을 시작합니다 ([run과 버전](../AI/Task_and_Record_Schema_agent.md#run과-버전-확장)).
